# Исправление микрофона Bluetooth-гарнитуры в Linux

Экспериментальный workaround для ситуации, когда Bluetooth-микрофон работает после подключения и в первом звонке, но замолкает после выхода и повторного входа в Google Meet, Discord, Zoom или другое приложение.

Подтверждённая причина — гонка жизненного цикла SCO/eSCO-соединения в ядре Linux. Контроллер успевает успешно создать mSBC eSCO-соединение после того, как ядро уже начало удалять ожидающий объект. Аудиопакеты приходят для неизвестного handle, `btusb` не включает изохронный USB endpoint, а приложение видит существующий, но полностью тихий микрофон.

Проект сохраняет качественный разговорный кодек **mSBC**. Он не включает CVSD, не отключает eSCO, не оставляет гарнитуру навсегда в телефонном режиме и не ухудшает A2DP вне звонка.

> [!WARNING]
> Это экспериментальное изменение ядра. Сейчас оно подтверждено только на Ubuntu 25.10, ядре `6.17.0-41-generic`, MediaTek MT7925 и HUAWEI FreeBuds Pro 4.

## Когда проект может помочь

- сразу после Bluetooth-подключения микрофон работает;
- первый звонок работает, второй — уже без голоса;
- переподключение Bluetooth временно исправляет проблему;
- микрофон остаётся видимым в PipeWire и браузере;
- ошибка появляется при переключении A2DP ↔ HFP/HSP;
- в журнале ядра есть `SCO packet for unknown connection handle`.

## Что меняется

Удаление ожидающего SCO/eSCO-соединения в состоянии `BT_CONNECT` откладывается на 2 секунды. За это время контроллер успевает прислать завершение соединения либо новый HFP-сокет успевает забрать существующий объект. Остальные типы Bluetooth-соединений и выбор кодека не меняются.

Дополнительно применяются два официальных upstream-исправления жизненного цикла SCO и гонки `sco_sock_connect()`. Подробности и ссылки находятся в английском [README.md](README.md) и [docs/root-cause.md](docs/root-cause.md).

## Диагностика

```bash
./scripts/diagnose.sh
```

Скрипт ничего не меняет и скрывает Bluetooth MAC-адреса. Перед публикацией всё равно проверь созданный файл: модели оборудования и версии системы остаются видимыми.

## Сборка и установка

```bash
sudo apt update
sudo apt install build-essential bzip2 dpkg-dev patch \
  "linux-headers-$(uname -r)"

./scripts/build-ubuntu.sh
sudo ./scripts/install.sh
sudo reboot
```

В release `v0.1.0` также будет готовый неподписанный модуль строго для `6.17.0-41-generic` вместе с контрольными суммами и соответствующим архивом исходников. Для любого другого ABI необходимо собирать модуль локально.

После перезагрузки:

```bash
modinfo -n bluetooth
modinfo -F vermagic bluetooth
```

## Откат

```bash
sudo ./scripts/uninstall.sh
sudo reboot
```

Установщик сохраняет предыдущий локальный модуль, а откат восстанавливает его. Если локального модуля не было, снова активируется штатный модуль Ubuntu.

## Ограничения

- Автоматическая сборка пока поддерживает только generic-ядра Ubuntu 6.17.
- После обновления ABI ядра модуль необходимо пересобрать.
- При включённом Secure Boot неподписанный модуль не загрузится; установщик остановится и ничего не ослабит.
- Это изменение ядра, поэтому необходимо оставить рабочее штатное ядро в меню загрузки.
- Для уверенности нужны отчёты с другим железом и длительные тесты.

## Как помочь

Создай issue и приложи результат `scripts/diagnose.sh`, модели гарнитуры и адаптера, пять повторных входов в звонок до/после фикса и используемый разговорный кодек. Не публикуй сырой `btmon`, не проверив наличие MAC-адресов и имён устройств.

Основная документация и актуальный статус проекта находятся в [README.md](README.md).
